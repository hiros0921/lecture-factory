# lecture-factory

撮影ゼロで動画講義を量産するパイプライン。台本を書けば、スライド・ナレーション・
字幕・動画・配信までが自動でつながります。

実運用で **26本 / 28分の講義動画** を作りました。ナレーションは本人の声を
クローンした合成音声です。かかった費用は**やり直し込みで約700円**（1本27円）。
台本を1行直せば、**90秒で作り直せます**。

---

## 何が難しかったか

工程をつなぐこと自体は難しくありません。実際に苦労したのは、
**AIが日本語を読み間違えること**と、**それを人手で確認しきれないこと**でした。

26本の動画には200個以上の音声が含まれます。全部を耳で聞くと数時間かかり、
集中力も持ちません。そこで検査を機械にやらせています。

### 二段階の自動検収

**B: 波形の検査**（[`tools/qc_audio.py`](tools/qc_audio.py)）
短すぎ・長すぎ・尻切れ・音割れ・無音落ちを、波形から判定します。

しきい値は実測して決めました。特に**「末尾ピークでは尻切れを判定できない」**
という発見が重要でした。正常な疑問文は語尾が上がるためピークが 0.287 まで上がり、
壊れた音声（0.235）より高くなります。原理的に分離できないので、
「末尾に無音があるか」での判定に切り替えています。

エンジンによって波形の性質がまったく違うことも実測で分かりました。

| 指標 | macOS `say` | MiniMax |
|---|---|---|
| ピーク | 0.35前後 | 0.83〜1.00 |
| 末尾無音 | 21〜59ms | 170〜306ms |
| 字/秒 | 7.19 | 6.10 |

MiniMax は設計上フルスケール付近まで音量を上げるため、**ピークでの判定が使えません**。
クリップ率で判定しています。

**C: 書き起こしとの照合**（[`tools/qc_transcribe.py`](tools/qc_transcribe.py)）
生成した音声を whisper で文字に戻し、元の台本と突き合わせます。

ここは表記ゆれとの戦いでした。台本が「あと」と書いても whisper は「後」と書きます。
文脈を見ない読み変換だと「のち」と読んでしまい、**正常な音声が大量に不合格**になります。
実際、最初の一括生成では21本中15本が停止しました。

形態素解析（fugashi + unidic-lite）に替えて解決しています。

| 入力 | 文脈を見ない変換 | 形態素解析 |
|---|---|---|
| そのあとから / その後から | あと / **のち** | アトカラ / アトカラ |
| そのとおり / その通り | とおり / **とうり** | トオリ / トオリ |

さらに whisper 自身の誤りに対しては、**照合専用の異表記表**
（[`assets/qc_aliases.json`](assets/qc_aliases.json)）を持っています。
TTS には一切影響しないので、後述のアクセント破壊が起きません。

## 誤読は辞書ではなく台本で直す

いちばん重要な知見です。

読み間違いを直す方法として最初に思いつくのは「読み方を辞書に登録する」ことです。
これは**半分正解で、半分間違い**でした。

かなで読みを指定すると読み間違いは直りますが、**イントネーションが平板になります**。
日本語の音声合成は漢字からアクセントを判断しているため、かなに開くと
手がかりが消えるからです。

実際、`AI → エーアイ` と登録したせいで全編で「アイ」にアクセントが乗っていました。
登録を外したら正しく「エー」に山が来ました。

**答えは、読み方を教えるのではなく、読み間違えない言葉に変えることです。**

| 型 | 例 |
|---|---|
| 同じ意味の別の漢字にする | `十分` → `充分`（「じゅっぷん」と読まれるのを回避） |
| 送り仮名を足して読みを固定する | `合言葉` → `合い言葉`、`間` → `間合い` |
| 別の語に置き換える | `部下` → `社員`、`録る` → `録音する` |

数字は表記を変えても直らないことが多く、`第7回` も `第七回` も誤読しました。
その場合は `今回は` のように数字ごと避けています。

読み替え辞書（[`assets/yomi_dict.json`](assets/yomi_dict.json)）は
**実際に間違えた語だけ**を最小限入れる運用にしています。

## 構成

```
pipeline.py          全工程の入口。--step で部分実行、複数回の一括実行に対応
tools/
  parse_script.py    台本(markdown) → segments.json
  make_slides.py     スライドHTML生成 → Chrome headless で1920x1080のPNG
  tts.py             音声生成。B/C の検収と最大3回のリトライを内包
  qc_audio.py        B: 波形の検査
  qc_transcribe.py   C: 書き起こし照合・語尾のイントネーション検査
  fixed_clips.py     D: 検証済みクリップの管理と結合
  verify_take.py     完全一致するまで生成し直して固定テイクを作る
  voice_clone.py     参照音声の前処理とボイスクローン作成
  fal_client.py      fal API のキュー方式クライアント
  telop.py           フルテロップ生成（音声の実測時間に文字数比で割り付け）
  assemble.py        スライド＋音声＋テロップ＋丸窓 → mp4
  make_cam.py        写真1枚から丸窓の講師映像を生成
  upload_r2.py       R2アップロード（読み戻し照合つき）
templates/           スライドのHTMLテンプレート
scripts/             台本（形式が分かる3本のみ収録）
```

### 固有名詞が何度やっても直らないとき

読み替え辞書では根治しない語があります。その場合は
「一度だけ完璧に読めたテイク」を作って使い回します。

```bash
python3 tools/verify_take.py "みなさん、こんにちは。" greeting
```

完全一致するまで生成を繰り返し、合格したものを保存します。以後その文で始まる
ナレーションは、クリップ + 0.25秒の間 + 残りのTTS を結合して作ります。

**声を変えたらクリップは作り直しが必要**なので、合わないまま実行すると
エラーで停止します（声が混ざるのを防ぐため）。

## 使い方

```bash
# 一気に全工程
python3 pipeline.py 01

# 本番に上げずに手元で確認
python3 pipeline.py 01 --skip-upload

# 部分実行
python3 pipeline.py 01 --step tts
python3 pipeline.py 01 --step qc        # 音声を作り直さず照合だけ

# まとめて
python3 pipeline.py --all --skip-done
```

### 必要なもの

- ffmpeg / ffprobe
- Google Chrome（スライドとテロップの描画）
- `python3 -m pip install fugashi unidic-lite mlx-whisper`
  - `mlx-whisper` は Apple Silicon 用。無い環境では openai-whisper のCLIに切り替わります
- fal.ai の API キー（音声生成に使用）

### 台本の書き方

```markdown
# 第1回：講座タイトル

## とびら: 第1回　講座タイトル
---
ここにナレーション。とびらスライドは大見出しだけが表示されます。

## セグメントの見出し
- 箇条書きポイント1
- 箇条書きポイント2
---
ここにこのセグメントのナレーション。話し言葉で書く。
```

`**強調**` はテロップで金色になります。1本あたり3箇所までにすると効果が保てます。

## 収録していないもの

- **配信側の Worker** — 稼働中サイトの認証に関わるため
- **台本23本** — 講座の中身のため（形式が分かる3本のみ収録）
- **音声・動画・スライド** — 生成物のため。台本から再生成できます
- **APIキー・声のデータ** — `.gitignore` 済み

## 権利と倫理について

このパイプラインはボイスクローンを扱います。運用にあたって次を守っています。

- クローンしてよいのは**本人の声、または書面で許諾を得た声のみ**
- AI音声を使った動画には**「音声はAIで生成しています」と明記**する
  （全スライドのフッターに自動で入ります）
- 声を直接保護する法律は日本にまだ整備されていないため、
  **各サービスの規約より一段厳しい自主ルール**で運用する
